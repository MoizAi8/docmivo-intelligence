# Test strategy and gates
Target 200 meaningful scenarios/checks if scope warrants; actual counts only. P0 coverage before count. Automated unit tests for parsing, normalization, ranking, highlight safety, schemas, citations, privacy policy and quotas. PostgreSQL integration tests (actual dedicated test DB): migrations, constraints, composite FK, query indexes, transactional ingest state, idempotency, concurrent quota reserve, search filter, deletion, rollback, ownership across all routes. No destructive tests on prod. Browser: real sign-in, upload supported synthetic PDF/TXT/DOCX, status, keyword, typo, filter, keyboard, exact source, saved search, AI answer citations, refresh, notes, delete, empty/error states. Two users attack every read/mutate/export/citation/download ID. Mock provider tests deterministic; separately bounded live Gemini calls only synthetic eligible content, verify answer vs known fixture, invalid cite rejection, insufficient evidence and non-sensitive opt-in; ensure zero network AI calls for PRIVATE docs and keyword search. Abuse tests: malformed file signatures, oversized upload, zip expansion, invalid encoding, parser timeout, XSS/SQL/prompt injection, quotas, auth, CSRF, access isolation. Performance: seeded 5k–10k chunks, warm API p50/p95, cold hosted, EXPLAIN, first load, upload latency, provider latency separate; no fictional metrics. Accessibility axe + manual keyboard focus and reduced motion. Screenshot widths 360/390/768/1280/1440/1920, landing/search/reader. Run lint, strict tsc, tests, npm audit, production build, hosted smoke. Capture real reports and screenshots under artifacts; redact secrets and use fictional data. Release report PASS/FAIL/BLOCKED/NOT TESTED per gate, distinguish physical devices vs emulation, automated vs manual, mocked vs live. No inflated counts. Public release blocked by insecure storage, cross-user exposure or fake inference.
